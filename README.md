# My Market App

Веб-приложение интернет-магазина. Пользователь просматривает каталог, ищет товары, добавляет их в корзину и оформляет заказы. Страницы формируются на сервере с помощью Spring MVC и Thymeleaf; данные хранятся в PostgreSQL.

## Возможности

- Каталог с поиском по названию и описанию без учёта регистра.
- Сортировка товаров по названию или цене и постраничный просмотр.
- Страница товара с описанием, изображением, ценой и количеством в корзине.
- Добавление товаров, изменение количества и удаление позиций из корзины.
- Расчёт стоимости корзины и оформление заказа с последующей очисткой корзины.
- История заказов и просмотр состава отдельного заказа.
- Загрузка изображений из файловой системы с заглушкой для отсутствующих файлов.
- Автоматические миграции БД и опциональная загрузка демонстрационных данных.

В приложении нет пользователей и авторизации: корзина и история заказов общие для всех посетителей. Оформление заказа сохраняет покупку в БД.

## Структура проекта

```text
my-market-app/
├── my-market-app-bom/       # Управление версиями зависимостей
├── my-market-app-api/       # Интерфейсы MVC-контроллеров, маршруты и перечисления
├── my-market-app-impl/      # Реализация приложения
├── images/                  # Изображения демо товаров и default-image.svg
├── Dockerfile               # Образ с Java 21 JRE и локально собранным JAR
├── docker-compose.yaml      # Приложение и PostgreSQL
└── pom.xml                  # Родительский Maven-проект
```

Модуль `my-market-app-api` описывает контракты контроллеров для HTML-интерфейса. Контроллеры передают запросы сервисам, сервисы работают с репозиториями, а мапперы подготавливают DTO для шаблонов.

## Настройки окружения

Настройки определены в [application.yaml](my-market-app-impl/src/main/resources/application.yaml), пример значений вынесен в [local.env.example](local.env.example).

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `DB_URL` | Нет, обязательна | JDBC-адрес PostgreSQL |
| `DB_USERNAME` | Нет, обязательна | Пользователь БД |
| `DB_PASSWORD` | Нет, обязательна | Пароль БД |
| `DB_SCHEMA` | `public` | Схема таблиц приложения и миграций Liquibase |
| `SERVER_PORT` | `8080` | HTTP-порт приложения |
| `IMAGES_ROOT` | `images` | Каталог изображений |
| `IMAGES_DEFAULT_IMAGE` | `default-image.svg` | Путь к заглушке относительно `IMAGES_ROOT` |
| `INSERT_DEMO_DATA` | `false` | Загрузка демонстрационных товаров и заказов |

## Локальный запуск

Нужны JDK 21 и доступная PostgreSQL. Maven устанавливать отдельно не требуется: в репозитории есть Wrapper. Все команды ниже выполняются из корня проекта; в Windows вместо `./mvnw` используйте `mvnw.cmd`.

Сборка и запуск JAR:

```sh
./mvnw package
java -jar my-market-app-impl/target/my-market-app-impl-0.0.1-SNAPSHOT.jar
```

Откройте [http://localhost:8080](http://localhost:8080). Корневой маршрут перенаправит на `/items`.

В примере включена загрузка демо-данных: каталог и примеры заказов. Без демо-данных новая база содержит пустой каталог; веб-интерфейса управления товарами нет.

## Запуск в Docker Compose

В [docker-compose.yaml](docker-compose.yaml) описаны сервисы `app` и `db`. PostgreSQL использует базу `my_market_app`, пользователя и пароль `market`. Приложение использует схему `public`, включает демо-данные, публикует порт `8080` и подключает каталог `./images` в `/app/images`.

Соберите исполняемый JAR локально на JDK 21. Docker должен быть запущен: интеграционные тесты используют Testcontainers. [Dockerfile](Dockerfile) копирует готовый JAR из `my-market-app-impl/target` в образ с JRE 21:

```sh
./mvnw clean package
docker compose up -d
```

Приложение доступно по адресу [http://localhost:8080](http://localhost:8080).

Остановка сервисов:

```sh
docker compose down
```

## Миграции и демо-данные

Liquibase запускается автоматически при старте приложения. [Главный changelog](my-market-app-impl/src/main/resources/db/changelog/db.changelog-master.xml) подключает файлы каталога `changes` в алфавитном порядке:

1. `001-create-tables.xml` — таблицы, первичные и внешние ключи, уникальность товара внутри заказа.
2. `002-create-indexes.xml` — индексы каталога и заказов.
3. `003-insert-demo-data.xml` — 12 товаров, 3 заказа и 8 позиций заказов при `INSERT_DEMO_DATA=true`.

## Изображения

В `items.image_path` хранится путь относительно `IMAGES_ROOT`, например `demo/coffee.jpg`. Для товара без изображения и для отсутствующего файла используется заглушка `images/default-image.svg`.

Сервис изображений проверяет, что файл находится внутри корневого каталога, в том числе после разрешения символических ссылок.

## Тестирование

Полный набор тестов:

```sh
./mvnw test
```

Требуются JDK 21 и работающий Docker. Testcontainers автоматически запускает `postgres:16-alpine`; отдельная тестовая БД не нужна. Профиль `test` отключает демо-данные, применяет миграции Liquibase и включает проверку схемы Hibernate (`ddl-auto: validate`).

Тесты проверяют бизнес-логику сервисов, MVC-маршруты, работу репозиториев и сценарий «каталог → корзина → покупка → история заказов». Интеграционные проверки включают откат транзакции при ошибке оформления заказа. Отчёты Maven Surefire находятся в `my-market-app-impl/target/surefire-reports/`.
